The Problem

AI decisions have consequences.
Data provenance is now law.

The EU AI Act creates binding obligations for organizations deploying high-risk AI. Most are unprepared.

EU AI Act — Key Requirements for High-Risk AI Systems

Organizations deploying AI in healthcare, finance, HR, legal, and other high-risk domains must comply with these articles by 2026–2027:

Art. 10 Data governance — training data must be documented, its origin verified, and modifications tracked with evidence of quality assurance.
Art. 12 Record-keeping — AI systems must maintain logs that allow post-hoc verification of data integrity and system decisions.
Art. 13 Transparency — providers must be able to demonstrate to authorities how the training data was governed and validated.

Features

Technical depth, practical use

Six independent modules. Each solves a specific part of the data provenance problem.

SHA-256 tamper detection

Every version gets a 64-character cryptographic fingerprint. Change one character — even a single space — anywhere in the file, and verify catches it instantly.

  • Detection works months or years after the modification
  • Works on any file type — CSV, JSON, Parquet, plain text
  • Mathematically impossible to modify a file and preserve its hash
  • Directly supports EU AI Act Article 10 data integrity requirements
$ python datavault.py verify data.csv
VERIFIED — data.csv is authentic
  Hash: 542c990c4b807b81...

# file modified externally

$ python datavault.py verify data.csv
TAMPERED — modified outside DataVault
  Current: e83595c8192dec21...
  Expected: 542c990c4b807b81...

Cryptographic hash chain

Each version's hash includes the previous version's hash — like a blockchain. Delete or reorder any version and the entire chain becomes invalid. You cannot rewrite history.

  • Same principle used in Bitcoin and certificate transparency logs
  • Cannot delete versions without detection
  • Cannot alter timestamps or commit messages
  • Supports Article 12 immutable record-keeping requirements
$ python datavault.py chain data.csv

  v1 | chain: 2036bd5dca2e583d... | prev: GENESIS
  v2 | chain: abc49ad45b50c280... | prev: 2036bd5d...
  v3 | chain: c3c9c2e752a82df4... | prev: abc49ad4...

CHAIN INTACT — 3 versions verified
  History is authentic and unmodified.

Row-level CSV diffing

Not just "the file changed" — DataVault tracks individual rows. See exactly which training samples were added, removed, or moved between any two versions.

  • Row identity based on content hash, not position
  • Detects reordering without false positives
  • Full history of one specific row across all versions
  • Critical for understanding dataset evolution in regulated contexts
$ python datavault.py rowdiff data.csv v1 v3

  Rows added: 4
  Rows deleted: 0
  Unchanged: 6

  ADDED rows:
  + {'id':'7','age':'38','income':'62000'}
  + {'id':'8','age':'41','income':'71000'}

Multi-user signing

Reviewers and approvers sign specific versions. Signatures are cryptographically tied to the file hash — modify the file after signing and the signature is automatically invalidated.

  • Four roles: reviewer, approver, owner, witness
  • Signature tied to exact file content, not just version number
  • Tampering with signature records is detected
  • Directly maps to Article 13 transparency and accountability requirements
$ python datavault.py sign data.csv v3 alice reviewer
$ python datavault.py sign data.csv v3 bob approver
$ python datavault.py approve data.csv v3

  Reviewer: ✓
  Approver: ✓
  Signatures: 2

APPROVED — ready for AI training

Version freezing

Lock a specific version so no further commits can be made without explicit authorization. Protected by passphrase (PBKDF2-SHA256) or owner signature.

  • Passphrase hashed with PBKDF2-SHA256 + random salt — never stored in plain text
  • Two methods: password (default) or owner signature
  • Blocked commits show exactly which version is frozen and how to unfreeze
  • Full audit trail — who froze, when, with what reason
$ python datavault.py freeze data.csv v3 "approved"
  Passphrase: ****
  Confirm: ****
+ Frozen data.csv v3 — passphrase protected

$ python datavault.py commit data.csv "change"
✗ data.csv v3 is frozen. Unfreeze first.

$ python datavault.py unfreeze data.csv v3
  Passphrase: ****
+ Unfrozen — authorized

Data quality analysis

Three analysis commands that go beyond version tracking to understand what changed and whether the data is trustworthy.

  • anomaly — detects missing values, duplicates, outliers, class imbalance, constant columns
  • diff --semantic — analyzes mean drift, distribution shifts, new categories
  • compare --statistical — deep statistical comparison with effect size (Cohen's d) and compatibility score
$ python datavault.py anomaly data.csv
  [HIGH ] CLASS IMBALANCE — 'label'
  Imbalance ratio: 22:1
  ⚠ May bias model training

$ python datavault.py compare data.csv v1 v3 --statistical
  income [SIGNIFICANT]
  mean drift: +13.2% effect size: 0.821 (large)
  COMPATIBILITY SCORE: 67%

Data lineage

Declare where your data came from — locally or across GitHub repositories. Verify that sources haven't been modified since you used them.

  • Local lineage — declare which files were combined to produce a dataset
  • Remote lineage — link to files in other GitHub repos with hash verification
  • Source integrity check — detects if a source has changed since the link was created
  • Directly supports EU AI Act Article 10 data origin requirements
$ python datavault.py link-remote training.csv \
  --repo https://github.com/user/medical-data \
  --file raw_scans.csv
+ Linked — hash verified ✓

$ python datavault.py verify-remote training.csv
✓ medical-data/raw_scans.csv — unchanged

Dashboard and reporting

A local web interface and exportable reports designed for both internal teams and external auditors.

  • Local web dashboard on localhost:5000 — no external service
  • Live file status — up to date, modified, or missing
  • Export full provenance report as HTML or print as PDF
  • Report format designed to be shown to regulators
$ python datavault.py dashboard
DataVault Dashboard → http://localhost:5000

$ python datavault.py export
+ Report exported to: datavault_report.html
  Files tracked: 2
  Total versions: 4
  Open in browser → Print → Save as PDF

Documentation

Up and running in 60 seconds

No pip install required. No configuration. No database. Python 3.6+ only.

1

Clone the repository

git clone https://github.com/thiminhkhuedao/DataVault.git cd DataVault
2

Or install via pip

pip install datavault-cli
3

Run the demo

Creates a dataset, commits 3 versions, simulates tampering, catches it, restores the clean version.

python test_datavault.py
4

Use on your own data

python datavault.py init my-project python datavault.py add dataset.csv "initial version" python datavault.py verify dataset.csv python datavault.py dashboard
