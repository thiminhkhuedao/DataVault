Features

Everything your data needs

Six independent modules. Use what you need, ignore the rest.

SHA-256 tamper detection

Every version gets a 64-character cryptographic fingerprint. Change one character anywhere in the file — even a single space — and verify catches it instantly.

  • Detection works even months after the modification
  • Works on any file type — CSV, JSON, Parquet, text
  • Fingerprint stored in .datavault/history.json
  • Comparison is instantaneous, no external service needed
$ python datavault.py verify data.csv

VERIFIED — data.csv is authentic
  Hash: 542c990c4b807b81...
  By: nguye
  Message: removed duplicate rows

# after secret modification

TAMPERED — modified outside DataVault
  Current: e83595c8192dec21...
  Expected: 542c990c4b807b81...

Cryptographic hash chain

Each version's hash includes the previous version's hash — like a blockchain. Delete or reorder any version and the entire chain becomes invalid.

  • Cannot rewrite history without detection
  • Genesis block anchors the entire sequence
  • Visual display in terminal with chainshow
  • Built automatically on every commit
$ python datavault.py chainshow data.csv

  v1 2026-07-25
  chain: 2036bd5dca2e583d...
  prev: GENESIS
           |
  v2 2026-07-25
  chain: abc49ad45b50c280...
  prev: 2036bd5dca2e583d...

CHAIN INTACT — 2 versions verified

Row-level CSV diffing

Not just "the file changed" — DataVault tracks individual rows. See exactly which samples were added, deleted, or moved between any two versions.

  • Row identity based on content hash, not position
  • Detects reordering without false positives
  • Full history of one specific row with rowhistory
  • Row snapshots stored automatically on each commit
$ python datavault.py rowdiff data.csv v1 v3

  Rows added: 4
  Rows deleted: 0
  Rows moved: 0
  Unchanged: 6

  ADDED rows:
  + {'id':'7','age':'38','income':'62000'}
  + {'id':'8','age':'41','income':'71000'}
  + {'id':'9','age':'33','income':'49000'}

Multi-user signing

Reviewers and approvers sign specific versions. Signatures are cryptographically tied to the file hash — modify the file after signing and the signature is invalidated automatically.

  • Four roles: reviewer, approver, owner, witness
  • Approval status check before training
  • Signature tampering detection
  • Full audit trail with timestamps
$ python datavault.py sign data.csv v3 alice reviewer
+ Signed data.csv v3 — alice (reviewer)

$ python datavault.py sign data.csv v3 bob approver
+ Signed data.csv v3 — bob (approver)

$ python datavault.py approve data.csv v3

  Reviewer: ✓
  Approver: ✓
  Signatures: 2

APPROVED — ready for use in AI training

Web dashboard

A local web interface that shows your full version history, file status, tags, and hash values. No external service, no account, no internet required.

  • Runs entirely on localhost:5000
  • Live status — up to date, modified, or missing
  • Visual version timeline with tags
  • Export provenance report as HTML or print as PDF
$ python datavault.py dashboard

DataVault Dashboard → http://localhost:5000
Refresh browser after any commit. Ctrl+C to stop.

$ python datavault.py export

+ Report exported to: datavault_report.html
  Files tracked: 2
  Total versions: 4
  Open in browser → Print → Save as PDF

Documentation

Get started in 60 seconds

No pip install. No config. No database. Just Python 3.6+.

1

Clone the repository

git clone https://github.com/thiminhkhuedao/DataVault.git cd DataVault
2

Run the demo

Creates a dataset, commits 3 versions, simulates tampering, catches it, restores the clean version — all in one command.

python test_datavault.py
3

Initialize your own project

python datavault.py init my-project python datavault.py add dataset.csv "initial version" python datavault.py verify dataset.csv python datavault.py dashboard

All commands

CommandDescription
init <name>Initialize a new DataVault project in the current folder
add <file> "msg"Start tracking a file and save the first version
commit <file> "msg"Save a new version after modifying a tracked file
log <file>Show full version history with hashes and authors
statusShow all tracked files and their current status
verify <file>Prove a file has not been tampered with since last commit
diff <file> v1 v2Text diff between two specific versions
checkout <file> v1Restore a file to a specific previous version
rowlog <file>Row change statistics across all versions (CSV only)
rowdiff <file> v1 v2Which rows were added, deleted, or moved (CSV only)
rowhistory <file> col valFull history of one specific row by column value
chain <file>Verify the full cryptographic hash chain
chainshow <file>Display the chain visually in the terminal
chainbuild <file>Build or rebuild the chain (run after migrate)
sign <file> v name [role]Sign a version as reviewer, approver, owner, or witness
signatures <file>List or cryptographically verify all signatures
approve <file> vCheck if a version has all required approvals
tag <file> v "label"Attach a human-readable label to a specific version
exportExport full history as an HTML provenance report
dashboardOpen the local web dashboard on port 5000
migrateBackfill row snapshots and chain for pre-existing versions
